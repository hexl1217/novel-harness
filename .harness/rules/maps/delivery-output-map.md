# 成稿交付清单（Delivery Output Map）

> 用途：**每次成稿交付的强制执行规范**。任何一次成稿（正文 / 章节 / 梗概细化 / 短剧分镜 / 短视频文案 / 审稿报告）完成后，交付物末尾必须附两块：
> ① **执行流程清单**（这一稿是怎么一步步做出来的）
> ② **规则坚持表**（这一稿坚持了哪些规则，逐条对照）
> 作用：让用户一眼看清"稿子怎么来的 + 规则是否被守住"，便于复盘、防漂移、防流程丢失。
> 依据：用户明确要求"每次写完，将执行流程列一个清单出来，然后规则也要重新坚持一遍，列一个表格，这个需要保存到项目"。

---

## 触发条件

- 用户说"写"、"写完"、"成稿"、"出稿"、"输出正文"等，且本 Agent 已完成一次正文/方案产出时，**必附**。
- 纯口头交流（没产出成稿）不附。

## 交付结构（成稿末尾追加）

### ① 执行流程清单

按**本次真实走过的步骤**列清单，不用模板空话。用表格：

| # | 流程步骤 | 做了什么 | 产出/结果 |
|:--|:---------|:---------|:---------|
| 1 | 需求澄清 | {本次实际问/确认了什么} | {结论} |
| 2 | 方向锁定 | {形态/平台/题材/字数如何确认} | {锁定值} |
| 3 | 构思/大纲 | {是否出过候选/细纲} | {选定结构} |
| 4 | 成稿 | {写了什么，字数} | {文件/正文} |
| 5 | 自检/去AI味 | {执行了哪几条检查} | {处理结果} |
| 6 | 规范先读（短剧/短视频成稿必填） | 读 `skills/h3-prompt-writing/SKILL.md` + 对应 `references/` | 列出已读文件名 |
| 7 | 本稿交付 | {附了清单+规则表} | — |

要点：
- 每行必须对应真实动作，禁止编造没做过的步骤。
- 若某步没做（如无大纲直接写），如实写"未做"并一句原因。
- **涉及 H3 提示词的成稿（短剧分镜 / 短视频分镜）**：第 6 行必填且必须列出实际读过的 skill 文件（如 `SKILL.md` + `references/ref-en.txt`）；未读视为流程未完成，不得交付（依据：`.harness/agents/短剧编剧Agent.md`「H3 先读后写」硬门禁）。

### ② 规则坚持表

列出**本稿适用的核心规则**，逐条标注符合情况与证据。

**凡可机器判定的规则以脚本输出为准**，附命令与合计行，不要只填一个 ✓ 了事 —— 自证填表对 LLM 近乎零成本，可判定的部分必须由脚本给出证据。两个脚本都要跑：

- `agent_core/check_draft.py` → **减法**（不该出现什么）
- `agent_core/draft_metrics.py` → **加法**（应该出现什么；只跑减法会让「合规但平淡」的稿子蒙混过关）

| 规则 | 要求 | 本次状态 | 坚持方式 / 证据（可引原句或描述） |
|:-----|:-----|:---------|:----------------------------------|
| 机器预检·减法 | 正文过 `agent_core/check_draft.py`，`error` 清零 | ✓ / — | {命令 + 合计行，如「2 个文件，0 error / 8 warn」；未跑须写原因} |
| 机器预检·加法 | 正文过 `agent_core/draft_metrics.py`，每条 `warn` 已判定「补 / 不改」 | ✓ / — | {命令 + 合计行 + 逐条处置，如「11 warn，9 条已补、2 条判定不改（理由）」；未跑须写原因} |
| 事实合规 | 稿中依赖的现实机制逐条可溯源（政策原文/审计报告/办事指南/F 编号）；无虚构制度动作 | ✓ / — | {依据清单，如「F1 平均 1 年最长 9 年、F5 虚假拨付、F11 免申即享」；纯架空写「不适用」} |
| 载体设计 | 主载体可被过手、被改写、最后回到起点；载体不必是实物 | ✓ / — | {载体类型 + 出场序列，如「一个说法，五处出场（出生→固化→传递→绕回→留种）」；无装置写「不适用」} |
| 字数先确认 | 动笔前锁定目标字数 | ✓ / — | {锁定值；未锁原因} |
| 判断句门禁 | 不用"不是X，是Y"式判定句，改场景呈现 | ✓ / — | {示例} |
| 情绪用动作落地 | 心理/情绪不直给标签，用手眼呼吸物件 | ✓ / — | {示例} |
| 对话不互相解释 | 角色不说清读者已知信息 | ✓ / — | {示例} |
| 段落/句式控制 | 长段拆短、句子随情绪走、不连续同节奏（**可判定部分见表零B**：均匀句串、极短句、均匀段串） | ✓ / — | {示例} |
| 感官与口气 | 视觉之外有别的感官；有角色口气、重复强调、停顿（**可判定部分见表零B**） | ✓ / — | {示例} |
| 结尾不硬升华 | 用动作/新信息/对话断开收尾，不总结升华 | ✓ / — | {示例} |
| 视角不越界 | 主角/NPC 不知不该知的信息 | ✓ / — | {示例} |
| 保护真人冗余 | 保留带口气的废话/吐槽/停顿 | ✓ / — | {示例} |
| H3 规范先读 | 写 H3 提示词前读 `skills/h3-prompt-writing/SKILL.md` + 对应 `references/` | ✓ / — | {已读文件：…；非短剧/短视频稿写「不适用」} |

- `✓` = 遵守；`✗` = 违反（须自报并说明已修或待修）；`—` = 本稿不适用（写原因）。
- 每次按**实际适用**的规则列表，不必死套 8 行；不足时按模块索引补充对应题材规则。
- 这是"重新坚持一遍"的自证，不是表演——有违规就如实填 ✗。

- 规则库或模块新增规则时 → 回本表追加对应行。
