# 审稿执行清单（Review Execution Checklist）

> 用途：审稿 Agent 每次审查的**强制执行清单**。从表一执行到表七，逐行勾选，不得跳项。
> 依据：human-linguistics / plot-review / rhythm-review / quality-check-map / 项目记忆 / 用户档案 / 历史案例。
> 每次审查报告必须附「执行进度表」，说明每行结果；跳过某项必须写明原因。

---

## 使用说明

1. 每次审稿先跑「表零A + 表零B」（机器预检，两个方向都要），再按题材补跑「表零C（事实合规）」「表零D（载体设计）」，最后从「表一」按编号逐行执行到「表七」，**不得跳项、不得凭感觉略过**。
2. 「触发条件」标 `必检` 的行每次都要做；标 `按类型` 的行仅按审查类型加载对应 skill 执行。
3. 某行跳过必须写原因（如「本次无新增设定，第 18 行跳过」）。
4. 报告末尾附「执行进度表」：每行编号 + `✓`（已检查）/ `✗`（发现问题，见报告）/ `—`（跳过+原因）；表零A、表零B 各贴自己的合计行，表零C、表零D 贴逐项判定。
5. 任一 `必检` 行未执行 → 审查不完整，补跑后再回传总编。
6. 本清单为活文档：新增 skill 规则或审稿维度时在此追加行，并更新 `module-index.md`。

---

## 表零 · 机器预检（必检，先于表一执行）

> 目的：把 `.harness` 规则里**可机器判定**的条款交给脚本执行，人在这一层不再逐条核对，只处理脚本报出的条目。
> 这样做的理由：自证式勾选对 LLM 近乎零成本，容易被形式化填成一行行 ✓；可判定的部分交给确定性程序，人工精力留给判断类问题。
>
> 两个方向都要跑：**表零A 查「不该出现什么」，表零B 查「应该出现什么」。**
> 只跑表零A 是历史遗留的漏洞 —— `check_draft` 全绿但通篇 AI 腔的稿子，只有表零B 能看出问题。
> 机器管不了的另两层用表零C、表零D 补：**表零C 查「这是不是真的」，表零D 查「装置立不立得住」。**
> 依据 `cases/feedback/2026-09-26-事实硬伤.md`：机检不覆盖事实层，全绿的稿子可以是彻头彻尾的编造。

| # | 检查点 | 规则来源 | 触发条件 | 结果 |
|:--|:-------|:---------|:---------|:-----|
| 0A | 运行 `python -m agent_core.check_draft <正文路径>`（或 `make check-draft`），把输出原样附在报告里。有 `error` → 先修再进表一；`warn` / `info` → 逐条判定「保留 / 修改 / 误报」并写一句理由 | `agent_core/check_draft.py`（条款来源：`语病诊断手册` 2.10–2.14、`参考_AI人性化正则规则` 5·8.1、`writing-execution-map` 段落与句子、`draft-output-map` 落盘与字数、`cases/feedback/2026-09-24-数字生硬.md`） | 必检（审查正文时） | |
| 0B | 运行 `python -m agent_core.draft_metrics <正文路径>`（或 `make draft-metrics`），把输出原样附在报告里。每条 `warn` → 逐条判定「补 / 不改」并写一句理由；**整段忽略视为未执行** | `agent_core/draft_metrics.py`（条款来源：`句式节奏档案` 4.1–4.6、`语病诊断手册` 2.3–2.9·2.11、`写作Agent` 场景三维度·Step 4、`human-linguistics/SKILL.md` 原则 1·2、`writing-execution-map` 段落与句子） | 必检（审查正文时） | |
| 0C | **事实合规专项**：逐条列出稿中依赖的**现实机制**，给出可溯源依据（政策原文 / 审计报告 / 办事指南 / F 编号）。凡虚构制度动作、术语口径错位、量级离谱者一律判失败。**机检不覆盖事实层**——表零A/B 全绿 ≠ 稿子可信 | `cases/feedback/2026-09-26-事实硬伤.md`（规则 1–4：事实合规优先于装置完整性、隐喻不豁免事实性、机检不覆盖事实层、装置设计正确顺序） | **必检（现实题材）**；纯架空题材写「不适用」 | |
| 0D | **载体设计专项**：确认主载体（实物 / 说法 / 状态 / 时间 / 身份）能否被**过手**、被**改写**、最后**回到起点**；列出各次出场的位置、形态、过手人、功能。**载体不必是实物**，选择标准是"能不能被过手、被改写、最后回到起点" | `cases/feedback/2026-09-26-事实硬伤.md`（规则 5：载体不必是实物；规则 6：讽刺落点优先留白） | 必检（有核心装置的稿；无装置写「不适用」） | |

**表零A 已覆盖、表二无需再逐条人工比对的部分**：T0 禁句（叙述 error / 对白 info 分级）、绝对禁用词与指纹词、AI 废话短语、进行病、身份重复标签、判定式短句、连续过渡词、单段 >60 字、单句 >45 字、**数字出场分层（算式独立成行 · 载体承载豁免 · 对白用汉字）**、标点规范化、正文路径与字数偏离。

**表零B 已覆盖、表二无需再逐条人工比对的部分**：长度相近句串与极短句（4.1）、同长度短段、连续等长对话、感官通道覆盖、重复强调缺失（2.11）、口语标记密度、把字句、停顿段、动作链（2.3）、情感标签（2.4）、因果链（2.5）、清单式罗列（2.6）、段尾盖章（2.8）、多余时间副词（2.9）、叙述内精确数值（原则 2）。

表二因此只做**判断类**复核：真人冗余该留还是该删、语感是否跟情绪走、梗是否过载、留白是好还是空洞 —— 这些脚本判不了。
