# 单章必读索引（Chapter Required Reading）

> 用途：把「写完一章到底要读多少规则」压到一页。
> 背景：本仓库 `.harness` 下有 78 个 md、约 10000 行规则（不含远程知识包）。此前单章流水线的默认加载集合约 **2913 行**，导致每章负担过重 —— 结果是「状态归档」这类看不见即时收益的步骤最先被跳过，而它恰好是长篇一致性的唯一数据来源。
> 本文件是**默认加载集合**的唯一入口。其余规则只在触发条件命中时加载，不再默认预读。

---

| 本文件 | 76 | 索引与触发条件 |
| **合计** | **268** | 原默认集合为 **2913 行** |

加上由上下文 Agent 提供的**上下文包**（主角状态、活跃伏笔、风格参考、约束提醒、最小记忆包）—— 这是每章真正的输入。

**就这些。** 不是「至少这些」，是「默认只有这些」。省下的约 2645 行不是被删了，而是改成了按触发条件加载（第三节）或交给机器（第二节）。

## 三、按需加载（触发条件命中才读）

| 触发条件 | 加载文件 |
|:---------|:---------|
| 写前输入散、章节目标不清 | `skills/plot-ideation/references/章节写前准备清单.md` |
| 切视角 / NPC 反应 / 怀疑信息越界 | `rules/maps/perspective-boundary-map.md` |
| 写后自检要判断水分、结构、五维评分 | `rules/maps/quality-check-map.md` |
| 涉及角色状态、伏笔登记、事件索引 | `rules/maps/state-tracking-map.md` |
| 规划阶段（不在单章写作路径内） | `rules/maps/planning-continuity-map.md` |
| 题材专项（数据化降临 / 游戏异界等） | `skills/game-datafied/SKILL.md` + `project-templates/模板-{题材}.md` |
| 用户说「太 AI 味」 | `skills/human-linguistics/rules/去AI味最小修改指南.md` |
| `check_draft` 报出某条语病，要看透成因 | `skills/human-linguistics/rules/语病诊断手册.md` 对应小节 |
| 需要题材语感 / 平台口气 / 场景细节 | `.harness/knowledge/`（经 RAG 查询） |

**判断类规则永远不在机器层**：什么算好对白、真人冗余该留还是该删、语感是否跟情绪走、梗是否过载 —— 这些必须由 Agent 判断，但它们也不该靠「通读 462 行正则规则」来保证。

## 四、审稿侧

审稿 Agent 的默认集合见 `review-execution-checklist.md`：**表零（机器预检）→ 表一~表七**。表零跑 `check_draft`，表二只复核判断类条目（真人冗余保护、语感、句式节奏），不再逐条比对机器已覆盖的 14 类语病。
