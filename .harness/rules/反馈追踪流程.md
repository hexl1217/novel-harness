# 反馈追踪流程

> 主模块 Step 4 的详细支撑文件。按需加载，仅在用户对输出提出否定时查阅。
> **本文件是反馈追踪机制的「流程 + 模板 + 目录约定」唯一实体源。**
> `cases/feedback/README.md` 只保留目录说明与指向本文件的指针，不再复述流程。

---

## 核心理念

每次用户说"不对""不是这样""不符合我的场景"，都是学习机会：

```
用户发现不对 → 记录问题 → 同类问题 ×3 → 升级为规则 → 系统变聪明
```

- 不接受模糊否定（"这个不对"必须有原因）
- 记录的是"用户纠正了什么"，不是"用户不满意"
- 3 次不是硬数字 —— 如果某次用户特别强烈（"每次都犯这个"），可以直接提前触发

---

## 核心流程

```
用户反馈"不对" → 
  1. 理解偏差：确认用户不满意的具体内容
  2. 记录反馈：按 cases/feedback/template-反馈记录.md 格式记录
  3. 查询同类历史：搜索 feedback/ 是否有相同类型的问题
  4. 如果同类问题已达 3 次：
     → 自动生成规则更新提案
     → 告知用户："同类问题已出现 3 次，建议追加规则：{提案}，是否确认？"
  5. 如果同类问题不足 3 次：
     → 记录在案
     → 提醒用户："同类问题已记录 {N}/3 次"
```

## 触发标准

以下情况算一次有效反馈记录：

| 场景 | 触发条件 | 记录内容 |
|:-----|:---------|:---------|
| **审稿意见被拒** | 用户说"这个不用改""你理解错了" | Agent 的判断方向 vs 用户的真实需求 |
| **修改结果被回退** | 用户手动恢复了 Agent 做的修改 | 修改的具体内容 vs 用户恢复后的版本 |
| **创作灵感不匹配** | 用户说"不是我要的方向""这个不符合场景" | 创作方向 vs 用户的实际需求 |
| **设定扩展被否决** | 用户说"这个设定和世界观不符" | 扩展方案 vs 用户的设定边界 |
| **连续修正** | 同一个问题上用户纠正了 Agent 2 次以上 | 这个问题的完整链路 |

## 3 次触发后的动作

1. 生成 rule_proposal.md（规则更新提案）
2. 建议追加到对应的规则文件
3. 等待用户确认后执行更新

## 文件命名与状态字段

**文件名格式**：`{YYYY-MM-DD}-{类型缩写}-{简短描述}.md`

| 类型缩写 | 含义 |
|:---------|:------|
| `review` | 审稿意见被拒 |
| `edit` | 修改结果被回退 |
| `idea` | 创作灵感不匹配 |
| `setting` | 设定扩展被否决 |
| `repeat` | 同一问题连续纠正 |

**`status` 字段（必填，写在「基本信息」里）**：区分「反馈执行了」与「规则登记了」两条线，
避免出现"稿子按反馈改了、规则没进库，下个项目重踩"的情况。

| 取值 | 含义 |
|:-----|:-----|
| `已执行` | 稿已按反馈产出，但规则尚未写入规则库 |
| `已登记` | 规则已写入规则库并登记于 `module-index.md`（须附「规则落点」） |

> 只写 `已执行` 的条目 = **技术债**。总编 Agent 启动时可扫描这些条目提示补登记。
> 依据：`2026-09-24-数字生硬.md` 曾自述"以按反馈执行的方式遵守，而非以规则已登记的方式"。

**记录模板**：`cases/feedback/template-反馈记录.md`

## 身份感知解读

| 用户等级 | 说"不对"可能意味着 | 应对方式 |
|:---------|:------------------|:---------|
| **Lv.1 零基础小白** | "我看不懂"/"太多了消化不了" | 简化建议，减少数量，更多对比示例 |
| **Lv.2 老书虫** | "我的直觉告诉我这样不对" | 多问"你觉得问题在哪"，帮他把直觉转化为具体规则 |
| **Lv.3 资深作者** | "我有更好的方案"/"你分析错了" | 直接讨论分歧，把作者的方案纳入规则提案 |
