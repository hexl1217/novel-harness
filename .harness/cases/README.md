# 案例库（Cases）

> 每次审稿/创作过程中发现的典型案例，结构化归档。
> 目标是积累足够多的正反案例，让 Agent 能从过往经验中学习。

---

## 目录结构

```
cases/
├── README.md              ← 本文件，案例库说明
├── template.md            ← 通用案例模板
├── 语病案例/               ← 对照案例（❌ AI 版 → ✅ 人写版）
│   └── 2026-09-25-第1则-AI腔整段对照.md
├── feedback/              ← 用户反馈记录（否定稿件的成因分析与修正）
│   ├── README.md
│   ├── template-反馈记录.md
│   └── 2026-09-24-数字生硬.md
└── user-profile/          ← 用户历史身份记录
    └── README.md
```

## 案例分类

| 类型 | 内容 | 来源 |
|:-----|:-----|:------|
| 语病案例 | 具体的 AI 语病 → 人写改法；含整段级的机器可判定对照 | `语病案例/` |
| 反馈记录 | 用户否定某一稿的成因拆解 + 已执行的修正 | `feedback/` |
| 用户档案 | 用户等级、偏好、历史口径 | `user-profile/` |

> 早前本文件写的 `审稿案例/`、`创作案例/` 两个目录从未建立，已移除；
> 完整的审稿过程记录在审稿报告里，不另存案例。

## 使用方法

1. 发现典型案例 → 按模板创建案例文件
2. 同类错误出现 3 次 → 考虑升级为高频规则
3. 定期回顾，合并重复，淘汰过时案例
4. **整段级的对照**（不是某一句写错，而是分布不对）优先做成
   `agent_core/test/fixtures/` 里的可回归样本，并在此登记 —— 只有这样它才会被持续验证
